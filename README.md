# lingzhu-app

Desktop client for the [lingzhu](../lingzhu) agent, built with Wails v3, React 19, Tailwind CSS and
shadcn/ui.

The app does not import the core. It starts `lingzhu serve` as a sidecar process (or reuses one that is
already running) and talks to it over HTTP + SSE. Only a core the app started is stopped when the app quits.

## Requirements

- Go 1.26+
- Node 20+ and npm
- Wails v3 CLI: `go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0`
- A built core: from the repository root, `go build -o build/lingzhu.exe ./cmd/lingzhu` (inside `lingzhu/`)

## Run

```sh
# from the repository root; builds the core once
cd lingzhu && go build -o ../build/lingzhu.exe ./cmd/lingzhu

cd ../lingzhu-app
wails3 dev          # hot reload
wails3 build        # production binary at ../build/lingzhu-app.exe
```

All artifacts live in the repository `build/` directory, next to the core and `config.json`:

```text
build/lingzhu.exe        core server
build/lingzhu-app.exe    desktop client
build/config.json        core configuration
build/data/              session logs
```

Because the app sits beside the core, it finds both the binary and the config without any
environment variables: the config makes its parent directory (the repository root) the agent
working directory.

At startup the app looks for the core binary next to itself, in `../build/`, and on `PATH`, and for a
config by walking up from the working directory (`config.json` or `build/config.json`). A discovered
`build/config.json` makes its parent directory the agent working directory.

## Environment

| Variable | Meaning |
|---|---|
| `LINGZHU_CORE` | Path to the core binary |
| `LINGZHU_ADDR` | Core address, default `127.0.0.1:8787` |
| `LINGZHU_WORKDIR` | Agent working directory |
| `LINGZHU_DATA_DIR` | Session data directory |
| `LINGZHU_CONFIG` | Core config file |

Core stdout and stderr go to `%LOCALAPPDATA%\lingzhu\app\core.log` on Windows
(`~/Library/Caches` / `~/.cache` elsewhere).

## Layout

```text
main.go              Wails app, window, service registration
service.go           Bridge: core lifecycle, session API, event forwarding
internal/core        HTTP/SSE client and sidecar process management
frontend/src         React UI (App, Sidebar, Messages, Composer, PermissionCard)
frontend/src/store           Zustand stores per domain and app bootstrap
frontend/src/components      Markdown, ContextMeter, Dialogs, Toast
frontend/src/lib             API bridge types, formatting and relative time
frontend/src/components/ui   shadcn/ui primitives (generated by `npx shadcn add`)
frontend/bindings    Generated from Go; not committed, run `wails3 generate bindings`
```

## Notes

- The UI uses a dark desktop design language: near-black surfaces, hairline borders, a warm
  peach accent, 13–14px type, one-line expandable tool rows and a permission dock above the composer.
- `src/index.css` is the single token source: OKLCH primitive scales feed semantic roles
  (`bg-*`, `fg-*`, `border-*`, `state-*`, overlays, `elevation-*`), and components only consume those
  roles. The app uses one `data-color-scheme="dark"` block; spacing stays on the 4px ladder, control
  heights are 24/28/32, reading width is measured in characters, focus is a 2px outline, hover/press are
  translucent overlays, and variants/states are driven by `data-*` attributes.
- The conversation uses an ordered session view: the transcript and composer share the
  `--container-session` width axis (744px); user turns are right-aligned bubbles capped at
  `min(82%, 64ch)`, assistant turns are borderless Markdown (14px / 160%), tool calls are 28px compact
  triggers that expand along a hairline rail, and copy/metadata chrome only appears on hover or focus.
- The composer uses an elevated editor: no border, `rounded-xl` with `elevation-raised` (0.5px light
  stroke, two soft dark shadows, a bottom inner highlight), a 13px / weight-440 draft surface, a 180px
  scrollport without a visible scrollbar, and one 44px control row (`+`, context readings, 28px square
  submit key that turns into Stop while a turn runs).
- Components come from shadcn/ui (radix-nova preset). `src/index.css` maps shadcn's semantic tokens
  (`--background`, `--border`, `--primary`, `--muted-foreground`…) onto the same roles, so
  `npx shadcn@latest add <component>` inherits the same look. Add new primitives under
  `src/components/ui` and use the `@/` alias.
- Transient outcomes surface as a top-center `Toast`; surface-bound failures stay in place. Rename,
  delete and workspace removal use `Dialog` instead of `window.prompt` / `window.confirm`.
- Frontend state lives in Zustand stores under `src/store` (notify, preferences, catalog, view,
  workspaces, chat). Stores are module singletons, so the tree has no provider chain; components
  subscribe to the slices they use, and one store reads another through `getState()`.
- Chrome (sidebar, header, tool triggers, permission dock, dialogs) is not selectable; message bodies,
  tool output, permission resources and inputs stay selectable.
- `LINGZHU_DEBUG=1` starts WebView2 with the DevTools endpoint on port 9222, so any CDP client
  (screenshots, console, DOM) can inspect the running window.
- Permission prompts arrive as `permission.asked` events and are answered through the core API, so the UI
  never talks to the core directly.
- Closing a connection does not stop a turn; the Stop button calls the interrupt endpoint.
- Sessions are durable in the core, so a client restart loses nothing.
